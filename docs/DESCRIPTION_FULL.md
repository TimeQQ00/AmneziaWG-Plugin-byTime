# AmneziaWG byTime — подробное описание проекта

**Автор:** Time · **Версия:** 1.0.0 · **Платформа:** exteraGram (Android, arm64-v8a)

---

## 1. Задача

В сетях с блокировками Telegram нужен обфусцированный туннель. Штатные
варианты неудобны:

- **Системный VPN** — требует отдельного приложения, разрешения VpnService,
  держит уведомление, конфликтует с другими VPN, тянет весь трафик телефона.
- **Прокси в Telegram** — публичные SOCKS5/MTProto быстро умирают, а
  самоподнятый сервер всё равно нужно где-то размещать.

Мы хотели: **включил — и Telegram работает через быстрый обфусцированный
протокол, без системного VPN, без root, без лишних приложений.**

## 2. Решение

Плагин exteraGram со **своим userspace-движком AmneziaWG**:

```
┌──────────────────────── exteraGram (процесс Telegram) ────────────────────────┐
│  Telegram (MTProto, медиа, превью)                                            │
│        │ TCP-запросы                                                          │
│        ▼                                                                       │
│  ProxySettings: 127.0.0.1:10809  ◄── ставится через SharedConfig/             │
│        │                              ConnectionsManager (внутренний API)     │
│        ▼                                                                       │
│  ┌──────────── libawgcore.so (наш движок, Go) ────────────┐                    │
│  │  SOCKS5-сервер (go-socks5)                            │                    │
│  │        ▼                                              │                    │
│  │  gVisor netstack (TCP/IP в userspace, без TUN)        │                    │
│  │        ▼                                              │                    │
│  │  AmneziaWG: ChaCha20 + обфускация Jc/Jmin/Jmax,       │                    │
│  │             S1-S4, H1-H4, I1-I5                       │                    │
│  └────────┬───────────────────────────────────────────────┘                    │
│           │ UDP (обычный сокет процесса)                                      │
└───────────┼────────────────────────────────────────────────────────────────────┘
            ▼
   AmneziaWG-сервер (какой укажете в вашем .conf)
```

Разница с обычным VPN-приложением: **нет VpnService, нет TUN-интерфейса,
нет системного уведомления.** Движок — это библиотека внутри процесса
Telegram, а «точкой входа» трафика служит обычный локальный SOCKS5-порт.

## 3. Из чего состоит

### 3.1 Движок `libawgcore.so` (Go, Android arm64)

Собран из трёх библиотек:

| Библиотека | Роль |
|---|---|
| `amnezia-vpn/amneziawg-go/v3` | протокол AmneziaWG (WireGuard + обфускация) |
| `gvisor.dev/gvisor` (netstack) | TCP/IP-стек в userspace: сокеты без TUN-устройства |
| `things-go/go-socks5` | SOCKS5-сервер на `127.0.0.1` |

C API (всего три функции — снаружи ничего больше не нужно):

```c
int awgStart(const char *configJson);  // 0 = ok, -1 = плохой JSON, -2 = ошибка старта
int awgStop(void);
int awgStatus(void);                   // 1 = работает
```

Ключевые решения:

- **`netstack.CreateNetTUN(...)`** — вместо TUN-устройства создаётся виртуальная
  сеть; адреса и DNS берутся из `.conf`.
- **DNS внутри туннеля** — SOCKS5-сервер отдаёт FQDN в netstack без разрешения
  на стороне Android, поэтому DNS-запросы идут через туннель.
- **Обфускация** передаётся в uapi-формат amneziawg-go напрямую:
  `jc/jmin/jmax`, `s1..s4`, `h1..h4`, `i1..i5` (включая формат сигнатур
  `<b 0x...>`, который понимает amneziawg-go v3).
- **Keepalive по умолчанию 25 с** — мобильный NAT не съедает сессию.


### 3.2 Python-часть (плагин exteraGram)

Обязанности:

1. **Загрузка движка.** `.so` лежит внутри файла плагина в base64; при первом
   запуске пишется в приватный каталог приложения (проверка sha256, запись через
   временный файл, `chmod 700`), затем `ctypes.CDLL`.
2. **Импорт конфигураций.** Три способа: кнопка «Выбрать .conf» (сканирует
   Download/Documents и предлагает выбор диалогом), импорт из буфера обмена,
   ручной путь (поддерживаются `file://` и `content://`). Разбор `.conf`,
   валидация, сохранение, применение. Пользовательский конфиг никогда не
   стирается автоматически — разовый провал проверки не стоит потери конфига.
3. **Включение прокси.** Через внутренний API Telegram — тот же путь, что
   используют штатные клиенты и плагин exitFy:

```python
info = SharedConfig.addProxy(ProxyInfo("127.0.0.1", port, "", "", ""))
SharedConfig.currentProxy = info
ConnectionsManager.setProxySettings(True, "127.0.0.1", port, "", "", "")
NotificationCenter.postNotificationName(NotificationCenter.proxySettingsChanged)
```

4. **Жизненный цикл.** Загрузка плагина → туннель; сворачивание приложения →
   туннель остаётся тёплым; возврат → проверка и «ленивый» реконнект;
   выгрузка → снятие прокси и остановка движка.

## 4. Импорт своих конфигураций

Плагин поставляется без встроенного сервера: при первом запуске он попросит
импортировать `.conf` (в личной сборке со встроенным конфигом он заработает
сразу). Подключение своего сервера:

```
Настройки плагина → «Выбрать .conf на устройстве» (или «Импорт из буфера обмена»,
или Путь к .conf → «Импортировать»)
```

Порядок работы:

1. Файл читается (формат `wg-quick`).
2. Строится конфиг движка (адреса без CIDR, DNS, MTU, все AWG-параметры).
3. Конфиг сохраняется в настройках плагина (`custom_config_json`).
4. Туннель перезапускается, затем **функциональная проверка**: SOCKS5-подключение
   к `1.1.1.1:80` внутри движка и ожидание ответа `HTTP/...`.
5. Успех → «Конфиг применён». Провал → туннель корректно останавливается
   с сообщением «ваш конфиг не заработал» (в личной сборке — откат на встроенный).

Поддерживаемые ключи `.conf`:
`PrivateKey`, `Address`, `DNS`, `MTU`, `Jc`, `Jmin`, `Jmax`, `S1`–`S4`,
`H1`–`H4`, `I1`–`I5`, `PublicKey`, `AllowedIPs`, `Endpoint`, `PersistentKeepalive`.

Кнопка «Сбросить конфиг» очищает пользовательский конфиг (и возвращает
встроенный, если он вшит в сборку).

## 5. Почему так, а не иначе

| Вопрос | Решение | Почему |
|---|---|---|
| Почему не VpnService? | userspace-стек | меньше разрешений, нет уведомления, нет конфликта с другими VPN |
| Почему SOCKS5, а не перехват трафика? | штатный механизм Telegram | стабильно, не требует хуков в сетевом коде |
| Почему движок внутри `.plugin`? | base64 в файле плагина | один файл для установки, ничего не тянется из интернета |
| Почему движок на Go? | amneziawg-go + gVisor | проверенная реализация протокола и стека, один `.so` |
| Почему не JNI? | `-buildmode=c-shared` + ctypes | три C-функции вместо обвязки на Java |

## 6. Производительность и расход

- Размер `.so`: **7.4 МБ** (arm64, `-s -w`), плагин целиком — 10.3 МБ.
- ОЗУ: ~30–60 МБ на процесс Telegram (стек + буферы).
- Скорость: ограничена каналом до вашего сервера; обфускация добавляет доли
  миллисекунды на пакет.
- Батарея: keepalive раз в 25 с — уровень обычного мессенджера.
- Порт: `127.0.0.1:10809` (при занятости — 10810…10814).

## 8. Ограничения

- Только TCP: звонки (UDP) идут напрямую, минуя туннель.
- Только `arm64-v8a`, Android 10+.
- Туннель живёт в процессе Telegram: если система убьёт приложение — туннель
  остановится; плагин поднимет его при следующем входе.
- Неверные ключи в конфиге движок принимает без ошибки — туннель просто не
  пропустит данные (плагин это отловит функциональной проверкой и остановится
  с понятным сообщением).
- Приватный ключ хранится в настройках плагина (для импортированного конфига)
  или в самом файле `.plugin` — только для ЛИЧНОЙ сборки со встроенным конфигом;
  публичную сборку и свой `.conf` не публикуйте.
